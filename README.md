# «Фотопринт» — единая система управления

Решение команды на Space Hackathon по ТЗ «Единая система управления компанией» (ред. 2.0), заказчик — ООО «Фотопринт» (picPac.by).
Три трека ТЗ сданы как **одна система**: клиент, команда и руководитель работают в одном потоке.

| | |
|---|---|
| Попробовать | **https://fotoprint.130-49-141-77.sslip.io** |
| Презентация | [`pitch/Презентация Фотопринт.pdf`](pitch/Презентация%20Фотопринт.pdf) · страница [`pitch/index.html`](pitch/index.html) |
| Демо-ролик, 53 с | [`demo-video/fotoprint-demo-16x9.mp4`](demo-video/fotoprint-demo-16x9.mp4) |
| Запуск у себя | `./start.command` или `python3 server.py` — нужен только Python 3.9+ |

Все данные в системе выдуманные. Ключей и паролей от настоящих систем в коде нет.

---

## 1. Три трека — одна система

| Трек | Что это | Для кого | Что даёт |
|---|---|---|---|
| Трек 2 | **Приложение picPac** — `/t2/` | клиент | Заказ с телефона и статус без звонка в поддержку |
| Трек 1 | **Пульт руководителя** — `/t1/` | директор, руководители отделов, аналитик | Показатели всех отделов, причина отклонения, решение |
| Трек 3 | **Помощник руководителя** — `/helper/` | руководители | Ответы по цифрам и документам, протоколы встреч, задачи |

Части связывает единый слой событий и статусов. Он объединяет события и **не заменяет** действующие системы — CRM, ERP, 1С, поддержку, кадры.

Общее у всех частей: один сервер, один вход и роли, один журнал действий, один ИИ-шлюз, одно оформление.

**Сквозной поток:**

1. Клиент оформил заказ в приложении.
2. Событие видно в пульте.
3. Участок отметил этап производства.
4. Клиент видит новый статус.
5. Помощник включил это в сводку руководителю.

## 2. Запуск

Ставить ничего не нужно — только Python 3.9 или новее.

    ./start.command              # macOS: запустит сервер и откроет http://127.0.0.1:8800/
    python3 server.py            # любая система, затем открыть http://127.0.0.1:8800/
    python3 server.py --lan      # ещё и для телефонов в той же сети

На главной — вход во все три части и кнопка «Сбросить демо-данные» (вернуть систему к исходному состоянию перед показом).

Без ключей моделей система работает на встроенной логике: показатели, причины, протоколы и ответы по документам считаются без ИИ.

### Тестовые учётные записи

Пароль у всех один: `demo2026` (лежит в `data/seed/users.json`).

| Логин | Роль | Что видит |
|---|---|---|
| `director` | директор | все отделы, все настройки, ИИ-шлюз |
| `production`, `sales`, `support`, `logistics`, `finance`, `hr`, `office` | руководитель отдела | только свой отдел — вглубь до заказа и причины |
| `analyst` | аналитик | все показатели и проверку качества данных |
| `operator`, `quality` | сотрудник участка | очередь своего этапа: «Принял» — «Сдал» |
| `client` | клиент | свои заказы в приложении |

Ролей с разными правами — 5. Права проверяет сервер по токену, а не экран: чужой отдел закрыт на сервере, отказ пишется в журнал.

## 3. Трек 1 — пульт руководителя

Вся компания на одном экране: видно, где нужно решение.

- **«Пульс компании»** — 11 сфер от «Сайта и приложения» до «Документов»; красным отмечены те, что ждут решения. При наведении сфера раскрывает свои задачи.
- **Шесть источников в одной картине:** CRM, ERP, поддержка, 1С, кадры, делопроизводство.
- **17 показателей** считаются из данных (норма ТЗ — не меньше 10). У каждой цифры — формула, источник и время обновления.
- **Каждый видит своё:** директор — всё, руководитель — только свой отдел.

### От показателя — к причине и решению

| Шаг | Что происходит | Пример |
|---|---|---|
| 1. Показатель | Загорелась красная лампочка | «Заказы в срок» — 91,1 % при плане 96 % |
| 2. Причина | Система сама проверяет версии по данным | Заказы застревают на сборке, там не хватает людей |
| 3. Решение | Карточка решения | Проблема, влияние, причина, действие, владелец, срок, приоритет |
| 4. Контроль | Решение не теряется | Реестр решений, история изменений, запись в журнале |

Ещё в пульте:

- **Прогноз на 6 недель** (норма ТЗ — 4): спрос и мощность производства, неделя дефицита и узкое место.
- **Можно ли верить данным:** свежесть источников, пропуски, дубли, сверка итогов с 1С — экран для аналитика.
- **Отчёт за период** одной кнопкой, за секунды — вместо 3–4 часов в 1С.
- **Заказы из приложения:** «Продажи и маркетинг» → «Приложение picPac — живые данные»; «Производство» → «Заказы из приложения: этапы и отметки».

## 4. Трек 3 — помощник руководителя

Спросил голосом — получил ответ. Провёл встречу — получил протокол.

- **Отвечает по цифрам пульта и документам** — со ссылкой на пункт и дату источника.
- **Режим «Встреча»:** слушает разговор и собирает протокол — решено, предложено, обсуждалось, требует уточнения; у поручений — владелец и срок.
- **Ничего не сохраняет сам:** предпросмотр → правка → подтверждение. Отмена не оставляет следов.
- **Знает не больше спрашивающего.** Зарплаты и персональные данные не раскрывает никому.
- **Ставится на экран телефона** как отдельное приложение — `/helper/`.

Замеры: 93 % поручений найдено в контрольных расшифровках (норма ТЗ — 80 %); 13 из 13 контрольных вопросов по документам; 30 из 30 разговорных вопросов голосом получают ответ по делу.

## 5. Трек 2 — мобильное приложение picPac

От фотографий в телефоне до оформленного заказа — меньше минуты.

Путь клиента: каталог → выбор продукта → загрузка фото → проверка кадров → макет → оформление → номер заказа → статус.

- **Само находит слабые кадры** — размытые, тёмные, дубли — и объясняет, что с ними делать. Проверка идёт на телефоне, фото никуда не уходят.
- **Без сети ничего не теряется:** черновик сохраняется, повторная отправка не создаёт второй заказ.
- **Статус приходит с производства:** участок отметил этап (экран участка — `/t2/admin.html`) — клиент увидел.
- **Ставится на экран телефона прямо с сайта**, без магазина приложений: страница «Скачать» с QR — `/get/`.
  Android — кнопка «Установить»; iPhone — Safari → «Поделиться» → «На экран „Домой“».

Замер: 37 секунд от каталога до номера заказа (фотокнига на 20 страниц из тестовой галереи). Сервер приложения покрыт 15 автотестами.

В папке `ios/` — нативное приложение для iPhone (Swift). По ссылке его раздать нельзя: Apple разрешает установку только через App Store или TestFlight.

## 6. Безопасность и ИИ-шлюз

Закрытая система: финансы и персональные данные не покидают компанию.

Любой запрос к модели — из пульта, помощника или приложения — идёт через **ИИ-шлюз** (`llm_gateway.py`). Это одна точка входа: он скрывает данные, считает лимиты и ведёт журнал. Модель подбирается под задачу:

| Задача | Кто отвечает | Запасной вариант |
|---|---|---|
| **Финансы** — маржа, прибыль, долги, зарплаты | только локальная модель | встроенные правила; в облако не уходит никогда |
| **Сложный разбор** — протокол встречи, документ | Claude, данные скрыты метками | DeepSeek |
| **Короткий ответ** — показатель, голос, чат | DeepSeek, данные скрыты метками | Claude |

**Три модели на выбор.** В системе подключены три модели: локальная, Claude и DeepSeek. По умолчанию шлюз сам подбирает модель под задачу, а в пульте можно выбрать, какой именно вы хотите пользоваться: «Данные и журнал» → «ИИ-шлюз». Там же, в «Последних обращениях», видно, какая модель ответила на каждый запрос.

Правила, которые выполняются всегда:

- Права проверяет сервер, а не экран. Отказ пишется в журнал.
- Имена, телефоны, УНП и суммы заменяются метками до отправки в модель.
- Решение за человеком: ИИ ничего не делает без подтверждения.
- Указания внутри документов — это данные, а не команды.
- Журнал: кто, когда, что сделал, с чем и с каким результатом.

## 7. Что получает каждый

Каждый видит общий поток, но только свою глубину данных и действий.

## 9. Как проверить самому

    python3 t2/test_app_api.py                 # 15 автотестов сервера приложения, запущенный сервер не нужен
    python3 server.py                          # дальше — в соседнем окне, при запущенном сервере
    python3 tools/eval_assistant.py            # протоколы, 13 контрольных вопросов помощника, права по ролям
    python3 tools/check_voice.py https://fotoprint.130-49-141-77.sslip.io   # 30 разговорных вопросов голосом — на стенде

Первые две проверки проходят и без ключей моделей. Проверка голоса рассчитана на подключённую модель, поэтому её адрес — стенд: без ключей помощник отвечает по готовым правилам главными отклонениями, и такие ответы проверка засчитывает не все.

Подробный отчёт — [`docs/Тестирование.md`](docs/Тестирование.md). Запросы сервера — [`docs/API.md`](docs/API.md). Сторонние компоненты и лицензии — [`docs/Лицензии.md`](docs/Лицензии.md).

### Переменные окружения

Все необязательные; кладутся в файл `.env` рядом с `server.py`, в репозиторий он не попадает.

| Переменная | Зачем |
|---|---|
| `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` | DeepSeek или другая модель с тем же форматом запросов |
| `CLAUDE_API_KEY`, `CLAUDE_MODEL` | Claude для сложных разборов |
| `LOCAL_LLM_URL`, `LOCAL_LLM_MODEL` | Локальная модель закрытого контура (Ollama, llama.cpp) |
| `AI_MODE` | Режим шлюза; по умолчанию `auto` — модель по задаче |
| `FP_AI_PER_DAY` | Дневной лимит обращений к моделям |
| `FP_PUBLIC` | `1` — режим открытого стенда: наружу отдаются только экраны, код и данные закрыты |
| `TG_BOT_TOKEN`, `TG_CHAT_ID` | Отправка задач в Telegram |

## 11. От прототипа к пилоту

Что это даёт уже сейчас: отчёт за период — за секунды вместо 3–4 часов в 1С; заказ с телефона — за 37 секунд; 93 % поручений со встречи попадают в протокол без секретаря.

Шаги до пилота:

1. **Доступ к настоящим данным** — соглашение о неразглашении, владельцы данных.
2. **Подключение вместо имитаций** — ERP, 1С, Битрикс24 через тот же слой событий; сами системы не меняем.
3. **Модель на сервере «Фотопринта»** — настоящий закрытый контур: данные не выходят с площадки.
4. **Пилот на одном отделе** — кадры или производство, затем остальные отделы.
