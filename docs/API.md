# Описание API

Общие адреса сервера (вход, хранилище, модель) описывает Илья, приложение picPac — Никита. Ниже — раздел помощника.

## Помощник руководителя (трек 3) — `/api/assistant/…`

Файл `assistant_api.py`. Все адреса требуют входа: заголовок `Authorization: Bearer <токен>` из `POST /api/login`. Без токена — `401`, для роли «клиент» — `403`. Права проверяет сервер **до** поиска и до отправки текста в модель.

| Метод и адрес | Что делает | Права |
|---|---|---|
| `GET /api/assistant/people` | Сотрудники `{id, name, title, role, dept}` и текущий пользователь `me` | любой сотрудник |
| `GET /api/assistant/docs` | Доступные документы с пунктами + `hidden` — сколько закрыто (названия закрытых не отдаются) | по правилам документа |
| `GET /api/assistant/docs/<id или код>` | Один документ, например `d10` или `ШР-01`. Чужой → `403` и запись «отказ» в журнал | по правилам документа |
| `POST /api/assistant/ask` `{q}` | Ответ по документам: `{answer, found, cites:[{doc, n, code, title, date, text}], hidden, searched, provider, fallback, masked, notes}`. Ссылки в тексте — `[D:d03:1]` | только доступные документы |
| `GET /api/assistant/meetings` | Встречи, где пользователь — участник (директор видит все) | участник / директор |
| `GET /api/assistant/meetings/<id>` | Встреча и расшифровка `{lines:[{t, s, text}]}`. Не участник → `403` + журнал | участник / директор |
| `POST /api/assistant/protocol` `{meeting_id}` | **Черновик** протокола, ничего не сохраняет: `{summary, points:[{text, status, line, t}], tasks:[{title, owner, due, line, quote, flags, suggested_owner, suggested_due}], risks, provider, fallback}` | участник встречи |
| `POST /api/assistant/protocol/confirm` `{meeting_id, key, summary, points, risks, tasks}` | Сохранить протокол и создать задачи — только после подтверждения пользователя. Повтор с тем же `key` возвращает уже созданное (`repeat: true`), другой `key` для утверждённой встречи → `409` | директор, руководитель-участник |
| `GET /api/assistant/tasks` | Задачи в зоне видимости роли + `hidden` | директор и аналитик — все; руководитель — свой отдел; сотрудник — свои |
| `GET /api/assistant/tasks/check` | Задачи без владельца или срока + предложение помощника (не применяется само) | как выше |
| `POST /api/assistant/tasks/<id>` `{status | owner | due}` | Изменить задачу, история и журнал. Нет прав → `403` + «отказ» | директор; руководитель своего отдела; сотрудник — только статус своей |
| `POST /api/assistant/feedback` `{ref, rating, comment}` | Оценка ответа (👍/👎 и комментарий) | любой сотрудник |
| `GET /api/assistant/audit` | Журнал действий | директор и аналитик — весь; руководитель — свой отдел; сотрудник — свои |
| `GET /api/assistant/access` | Матрица «документ × сотрудник» | директор, аналитик |

### Правила доступа к документам (`data/seed/documents.json`, поле `access`)

- `all` — все сотрудники; `heads` — руководители отделов; `analyst` — аналитик;
- `dept:<отдел>` — руководитель и сотрудники отдела; `head:<отдел>` — только руководитель отдела;
- директор видит всё; `sensitive` (зарплаты) — документ можно открыть по правам, но помощник не использует его в ответах ни для кого.

### Статусы

- Пункты протокола: `решено`, `предложено`, `обсуждалось`, `требует уточнения`.
- Задачи: `new`, `in_progress`, `done`, `needs_info` (нет владельца или срока).
- Просрочка вычисляется по сроку; даты — `ГГГГ-ММ-ДД`, время событий — с часовым поясом.

### Данные помощника

- `data/seed/documents.json` — 20 документов с уровнями доступа (только чтение).
- `data/seed/transcripts.json` — 3 расшифровки; `tr-1` — контрольная.
- `data/seed/meetings.json`, `data/seed/tasks.json` — встречи недели и стартовые задачи (коллекции `meetings`, `tasks`, сбрасываются кнопкой «Сбросить демо-данные»).
- `data/seed/people_aliases.json` — как к сотрудникам обращаются в речи (для разбора поручений).
- `data/eval/control.json` — эталон для проверки (задачи, пункты, контрольные вопросы).

## Мобильное приложение picPac (трек 2) — `/api/app/…`

Файл `app_api.py`, адреса `/api/app/…`. Вход общий: `POST /api/login` → токен, дальше `Authorization: Bearer <токен>`.
Ошибки — JSON `{"error": "понятный текст"}`, иногда с `field` (какое поле исправить). Деньги — строки с двумя знаками, валюта BYN. Время — с часовым поясом.

## Публичные
| Адрес | Что |
|---|---|
| `GET /catalog` | Каталог: 5 продуктов (фотопечать, фотокнига, календарь, магнит, холст), варианты, цены, требования к фото, сроки; способы получения и пункты выдачи |
| `POST /price` | `{items:[{product,variant,qty,options}], delivery, promo}` → цена с разбивкой (МП-04) |
| `POST /guest` | Вход гостем → `{token,user}` |
| `POST /step` | `{step: catalog\|photos\|layout\|check\|cart, session}` → событие `app_step` для воронки пульта |

**Формула цены.** `итого = товары − скидка + доставка`. Фотопечать: ступенчатая цена за штуку (от 50 и от 200 шт). Фотокнига: `база + (страницы − 20) × цена доп. страницы`. Остальное: `цена × количество`. Скидка по промокоду считается от товаров (BOOK15 — только от фотокниг). Доставка Белпочтой бесплатна, если товары после скидки от 150 BYN. Всё считает сервер; клиент присылает только выбор.
Тестовые промокоды: `PICPAC10` (−10 %), `WELCOME5` (−5 BYN от 30 BYN), `BOOK15` (−15 % на фотокниги).

## Клиент (только свои данные, проверка по токену)
| Адрес | Что |
|---|---|
| `GET /projects`, `POST /projects` | Список и создание черновика (МП-03: продукт, фото, порядок, кадрирование, опции) |
| `GET /projects/<id>`, `POST /projects/<id>` | Чтение и сохранение; клиент сам выбирает id, поэтому черновик, созданный без сети, сохраняется под тем же id. Версия `version`; при `base_version` меньше серверной ответ 409 (без `force`) |
| `POST /projects/<id>/delete` | Удалить проект |
| `GET /projects/<id>/check` | Проверка перед заказом: мало пикселей, размытые, тёмные, пустые места, лишние фото, обрезка. Уровни: `error`, `warn`, `info` |
| `POST /photos` | Тело — файл JPEG или PNG (до 25 МБ, от 400 px по короткой стороне); заголовок `X-Photo-Id` задаёт id (МП-02). Повторная загрузка с тем же id заменяет файл |
| `GET /photos/<id>`, `POST /photos/<id>/delete` | Скачать и удалить своё фото (МП-06) |
| `POST /orders` | Заказ. Нужен заголовок `Idempotency-Key`: повтор с тем же ключом возвращает уже созданный заказ с `replayed: true` (МП-05). Цена пересчитывается на сервере. Есть замечания `warn` — 409 и `needs_accept`, пока клиент не передаст `accept_warnings: true`; `error` — 422 |
| `GET /orders`, `GET /orders/<id>`, `GET /orders/<id>/events` | Свои заказы и лента статусов. Чужой заказ — 404, в журнал пишется «отказ» |
| `POST /support`, `GET /support` | Обращение `{order_id, text, topic}` → запись `interaction` со сроком ответа `due` (4 часа). Тоже принимает `Idempotency-Key` |
| `POST /account/delete` | `{confirm:true}`: удаляет файлы, проекты и тексты обращений; заказы остаются обезличенными (учёт). Гость удаляется целиком, тестовая запись `client` очищается и остаётся |

## Сообщество: отзывы и шаблоны (`/api/app/social/…`)
Читать ленту можно без входа; всё остальное — по токену. Публиковать шаблоны, отвечать на отзывы и скрывать их могут только `director` и `head`; отказ пишется в журнал.
| Адрес | Что |
|---|---|
| `GET /social/feed` | `{templates, reviews, summary:{count,avg,dist}, occasions, can_publish, my_orders}`. Шаблоны picPac (6 штук) есть всегда, свои компании идут выше. Три отзыва-примера помечены `demo:true`. Скрытые отзывы видны только автору и сотрудникам |
| `POST /social/reviews` | `{order_id, rating 1–5, text 10–600 знаков}`. Только по своему заказу; один отзыв на заказ (повтор правит его, код 200). Ссылки и контакты в тексте — 422 |
| `POST /social/reviews/<id>/like` · `/delete` · `/reply` · `/hide` | Отметка «полезно» (переключатель); удаление своего отзыва; ответ компании `{text}`; скрыть/показать |
| `POST /social/templates` | Шаблон `{title, desc, product, variant, options:{pages}, per_page 1–4, occasion}`; поддерживает `Idempotency-Key` |
| `POST /social/templates/<id>/like` · `/use` · `/delete` | Отметка, счётчик «использовали», удаление (шаблоны picPac удалить нельзя) |
Коллекции: `reviews`, `templates`, `social_stats` (лайки и счётчики). «Удалить мои данные» удаляет и отзывы пользователя.

## Сотрудники
| Адрес | Кто | Что |
|---|---|---|
| `GET /staff/orders` | operator, head, director, analyst | Очередь; оператор видит только свой этап, поле `can` — можно ли отмечать |
| `POST /staff/orders/<id>/mark` | по этапу | `{action: accept\|handoff\|defect}` — «Принял / Сдал / Брак» |
| `GET /staff/support` | сотрудники | Все обращения |

Права на этапы (проверка на сервере, отказ пишется в журнал): `operator` — модерация и производство; `quality` — контроль качества, передача в доставку, завершение; `head` производства — модерация, производство, контроль; `head` логистики — передача и завершение; `director` — все.

## События (коллекция `events`)
- `{type:"order_status", order_id, stage, status, actor, ts, key}`; этапы: `accepted` → `moderation` → `production` → `quality` → `shipped` → `done`; `status`: `pending` (ждёт), `started` (принял), `passed` (сдал), `defect` (брак). По парам `started`/`passed` пульт считает время участка.
- `{type:"app_step", step, session, ts}` — воронка: каталог → фото → макет → проверка → корзина → оплата.

## Заказ (коллекция `orders`)
`id, number (PP-1001…), channel:"mobile", customer_id, stage, stage_status, status (= stage), items[], goods, discount, promo, total, currency, delivery, pickup_point, address, name, phone, ready, eta_days, time_sec (секунд от выбора фото до заказа), ts`.
Коллекции приложения: `projects`, `interactions`, `uploads_meta`; файлы фото — `data/uploads/<пользователь>/`.

## Что хранится и как удалить
Фото, проекты, обращения, заказы. Удаление клиентом — `POST /account/delete`; для всей системы — кнопка «Сбросить демо-данные» (удаляет коллекции; файлы `data/uploads/` и гостей чистит `rm -r data/uploads`).
