# Локальный ИИ на ноутбуке — отчёт о развёртывании

Развёрнуто в ночь с 11 на 12 ноября 2026, удалённо по SSH с ноутбука Ильи. Всё лежит в `D:\fp-ai` (около 11,6 ГБ вместе с запасной моделью на 8 миллиардов параметров). Система, драйверы, PATH и настройки защиты Windows не менялись.

## Что не прошло — сразу

1. **Порог ТЗ «найти не меньше 80 % задач в расшифровке» сначала не проходил** (9 из 15, 60 %). После разбора длинной расшифровки по частям — **13 из 15 (87 %), порог выполнен** (два прогона подряд, см. раздел «Разбор по частям»). Запас небольшой: локальная модель добавляет 1–3 лишние задачи на встречу и иногда ошибается в статусе пункта; облачная точнее.
2. **Голос Silero не скачался:** сайт `models.silero.ai` в этой сети обрывает защищённое соединение. Через VPN обходить не стали; поставлен запасной движок Piper (как и записано в инструкции).
3. **Большая модель распознавания на процессоре слишком медленная** (30 с на 6 с речи). Работает малая.
4. **С телефонов стенд на этом ноутбуке не открыт:** порт 8800 в брандмауэре не открывали. Показ — с самого ноутбука.

## Что пришлось поправить в коде

- `server.py`: для локальной модели короткие ответы идут без «размышлений» (чтобы голос не запаздывал), большие разборы — с ними; время ожидания локальной модели увеличено до 240 с.
- `assistant_api.py`: владелец задачи вида `@u-hr` теперь распознаётся как `u-hr`. Без этого у локальной модели не засчитывалась ни одна задача (0 из 15), хотя она их находила.
- `assistant_api.py`: в локальном режиме длинная расшифровка разбирается по частям (по 8 реплик, 2 реплики перекрытия), найденные задачи, пункты и риски сводятся без повторов, общий итог пишется отдельным коротким запросом. Облачный режим работает как раньше — расшифровка уходит целиком. Номер реплики принимается и строкой («[5]»).
- `server.py`: модулям доступен текущий режим ИИ (`core.mode()`).

## Как запускать и останавливать

На самом ноутбуке:
- **Запуск:** двойной щелчок по `D:\fp-ai\START.bat`. Через 20–30 секунд открыть `http://localhost:8800/`.
- **Остановка:** `D:\fp-ai\STOP.bat`.
- Журналы — `D:\fp-ai\logs\`. Проверка всей цепочки: `D:\fp-ai\python\python.exe -X utf8 D:\fp-ai\test_ai.py`.
- Те же скрипты лежат в репозитории: `tools/windows/`.

Параметры `start-ai.ps1`: `-Ctx 4096` (меньше видеопамяти), `-Whisper ggml-large-v3-turbo-q5_0.bin`, `-WThreads 12`, `-Lan` (открыть стенд в сеть — понадобится правило брандмауэра).

## Что важно знать перед показом

- **Запускать нужно с самого ноутбука.** При проверке службы запускались из удалённого сеанса и живут, только пока он открыт.
- **«Интеллектуальное управление приложениями» Windows включено.** При первом запуске оно один раз заблокировало библиотеку Piper как незнакомую; со второго запуска пропустило. Если синтез не поднялся — запустить `START.bat` ещё раз. Защиту не отключали.
- **Памяти в обрез:** свободно около 2 ГБ. На время показа закрыть лишние программы и вкладки.
- **Ноутбук — от розетки**, сон отключить.
- **Протоколы встреч локальная модель теперь разбирает** (87 % задач), но это занимает 20–40 с на встречу, и в списке бывают лишние задачи — перед показом пробежать протокол глазами. Облачная модель точнее и быстрее; если данные показа можно отправлять в облако, для протоколов лучше она.
- Доступ по SSH для развёртывания: правило брандмауэра `sshd-claude` (только с адреса ноутбука Ильи) и ключ в `C:\ProgramData\ssh\administrators_authorized_keys`. После хакатона убрать: `Remove-NetFirewallRule -Name sshd-claude`, удалить строку ключа, при желании `Stop-Service sshd`.

Обе локальные модели хорошо разбирают короткие встречи (75–100 % задач) и теряют поручения в длинной: из 8 находят 3. Похоже, дело не в размере модели, а в длине разговора.

## Разбор по частям (12.11, ночь)

Догадка подтвердилась: дело было в длине разговора. В локальном режиме расшифровка длиннее 10 реплик теперь делится на части по 8 реплик с перекрытием в 2 реплики; каждая часть — отдельный короткий запрос к модели, затем задачи сводятся без повторов.

| Расшифровка | Явных задач | Прогон 1: найдено / лишних | Прогон 2: найдено / лишних |
|---|---|---|---|
| tr-1 (контрольная, длинная) | 8 | 7 / 3 | 7 / 2 |
| tr-2 | 4 | 3 / 2 | 3 / 1 |
| tr-3 | 3 | 3 / 0 | 3 / 0 |
| **Всего** | **15** | **13 (87 %)** | **13 (87 %)** |

- Статусы пунктов протокола tr-1: 6 из 6 в первом прогоне, 4 из 6 во втором.
- Весь проверочный набор (три встречи и 13 вопросов по документам) проходит за 114–115 с.
- Облачный режим этой правкой не задет: проверен отдельным прогоном на DeepSeek (14 из 15, расшифровка уходит целиком, как раньше).
- Размер части меняется переменной окружения `LOCAL_PROTO_PART` (по умолчанию 8; 0 — не делить).

Что остаётся слабым: лишние задачи (модель иногда записывает как поручение то, что было просто сказано) и две не найденные задачи из 15.
